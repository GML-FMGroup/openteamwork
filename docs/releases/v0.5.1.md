# OpenPPX v0.5.1 Developer Preview

> 状态：GitHub Pre-release。它面向开发者测试，不应描述为稳定或生产就绪版本。

`v0.5.1` 延续 OpenPPX Desktop 与 OpenPPX Node 前后端分离的方向，重点补齐连接可靠性、客户端边界和桌面工作区体验。Desktop 可以在一台机器上管理多个 Agent，并通过 Client API 连接本机或可信局域网中的 OpenPPX Node。

## 本版本包含

- 抽取可复用的 `@openppx/client` TypeScript 包，统一 Client API 模型、协议校验、认证、投影和 HTTP/SSE 传输。
- 将 Electron Main 中的连接、Session/Message 缓存、Run 事件流、本地 Node 监督和显式开发桥接拆分为独立服务。
- 支持带 `Last-Event-ID` 的有界 SSE 重连、重复事件抑制、真实 Run 取消和非重叠 Node 健康检查。
- 连接恢复后重新获取 Agent、Session 和消息状态；本地 Node 与局域网 Node 保持不同的控制边界。
- 重构 Renderer 状态层，将工作区、活跃 Run、连接恢复和对话跟随逻辑从应用壳中拆出。
- 精修三栏工作区、Settings、消息、Composer、Progress 和 Artifacts；用户消息靠右显示，外层面板图标保持一致。
- 左栏和右栏支持拖拽调宽、键盘调整、双击复位和本地持久化，同时保护中央对话区的最小可用宽度。
- 修复 ADK 运行依赖和同步/异步 eval loader 兼容性。

## 架构边界

```text
OpenPPX Desktop
  -> Electron Main / secure credential store
  -> @openppx/client
  -> Client API v1 (HTTP + SSE)
  -> OpenPPX Node (Python + Google ADK)
  -> one or more configured agents
```

Desktop 是薄客户端，不包含 Python 后端、模型凭证、Agent 配置或用户数据。局域网 Token 由 Electron Main 的安全存储负责，不进入普通连接配置或 Renderer。

## 已知限制

- 仅验证 macOS Apple Silicon；尚无 Windows、Linux 或 Intel macOS 安装包。
- macOS DMG 未进行 Apple Developer ID 签名或 notarization，系统可能显示来源验证提示。
- OpenPPX Node 仍需单独安装、配置和运行。
- 真实的两台物理机器局域网验收尚未完成；当前不能把单机 loopback 测试等同于完整远程验收。
- 局域网模式只适用于可信网络，不应将 Client API 端口直接暴露到公网。
- 尚未提供自动 TLS、SSH tunnel、Tailnet 或公网 Relay 配置。
- 当前只支持一个连接目标；多 Node 列表、自动发现和配对仍属于后续规划。

## 发布验证

发布候选需要通过 Python、TypeScript Client 和 Desktop 的完整测试，并验证 wheel 元数据与安装、DMG、SHA-256 清单、preload 文件以及打包后 App 的启动路径。具体安装与构建方式见仓库根目录及 `apps/desktop/README.md`。
