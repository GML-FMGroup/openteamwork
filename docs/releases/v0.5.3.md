# OpenPPX v0.5.3 Extension Platform Preview

> 状态：GitHub Pre-release。它面向开发者测试，不应描述为稳定或生产就绪版本。
> 版本边界：本文“本版本包含”和“发布资产”只描述 `v0.5.3` tag 已上传的不可变制品。tag 之后主分支新增的文件安全与 Artifact 闭环将进入后续版本，不能据本文反向宣称现有下载资产已经包含。

`v0.5.3` 完成了 OpenPPX Extension 平台的第一轮产品化闭环。Node 继续作为扩展资源、信任、配置和 Agent 授权的唯一事实来源；CLI、Desktop 以及未来 Mobile 客户端通过统一 Client Contract 使用这些能力。

## 本版本包含

- 明确长期 Extension 分类：Plugin 是可移植的复合能力包，App 是公开产品连接，MCP Server 是标准协议端点，Skill 是符合 `SKILL.md` 标准的技能包。
- Plugin 改用 Codex 兼容的 `.agent-plugin/plugin.json` 结构，支持 Skills、MCP、Apps、Hooks 和 Assets 组合，不再依赖 OpenPPX 私有包格式。
- 建立 Node 管理的 Extension 生命周期，包括发现、预览、安装、更新、删除、启停、修订冲突和 Agent 授权。
- 引入原生 App Adapter SPI；App 可以由可信 Plugin 适配，也可以投影到共享 MCP 运行时，不把产品分支写进核心执行路径。
- 提供 143 个经过分类的候选入口：42 个 Apps、4 个原始 MCP Servers 和 97 个标准 Skills。
- Desktop 补齐 Plugin、App、MCP Server 和 Skill 的新增、编辑、配置、连接与移除流程。
- 为常用产品增加本地 SVG 图标和稳定展示元数据，不请求远程图片，不通过名称猜测资源。
- Extensions 页面采用紧凑的单列分组列表、统一行分割线、胶囊操作按钮和八项折叠，降低卡片墙与重复状态信息造成的视觉噪声。
- 修复 Extensions 长列表滚动与打包后 preload/Client Contract 边界问题。

## Extension 边界

```text
Plugin (.agent-plugin)
  ├─ Skills
  ├─ MCP Servers
  ├─ Apps
  ├─ Hooks
  └─ Assets

App                 MCP Server              Skill
Known product       Raw protocol endpoint   Standard SKILL.md
Native/MCP-backed   Standard MCP config     Portable guidance
```

Node 保存资源与凭据引用、执行预览和信任校验，并为每次 Run 生成不可变能力快照。Desktop 只负责呈现和发起受治理的 Action，不直接修改 Extension 文件。

## 已知限制

- 仅验证 macOS Apple Silicon；尚无 Windows、Linux 或 Intel macOS 安装包。
- macOS DMG 未进行 Apple Developer ID 签名或 notarization，系统可能显示来源验证提示。
- OpenPPX Node 仍需单独安装、配置和运行。
- 部分 App 候选只有确定的标准协议入口；需要专有适配代码的候选会明确显示尚不可用或依赖要求。
- 真实两台物理机器的完整局域网验收尚未完成；局域网模式仅适用于可信网络。
- 不应将 Client API 端口直接暴露到公网；自动 TLS、SSH tunnel、Tailnet 和公网 Relay 尚未产品化。
- 当前发布资产的附件链路仍以当时的通用 Session Artifact 能力为准；主分支随后补齐的 DOCX/XLSX/CSV/PDF/PPTX/图像内容校验、受限提取和 Session Artifact 生命周期不属于已上传资产。

## 发布验证

发布候选通过 Python Extension/Action/Contract 测试、TypeScript Client 测试、Desktop 测试、严格 TypeScript、Electron preload、生产构建、打包后 ASAR 检查和 macOS App 视觉验收。发布资产另外执行 wheel 安装验证、DMG 完整性检查和 SHA-256 校验。
