# OpenPPX Desktop v0.5.0-beta.1 Developer Preview

> 状态：本地发布候选，尚未公开发布。

这是合并 `ppx-client` 与 OpenPPX 后的首个桌面端 Developer Preview。当前目标是尽快提供一条诚实、可演示、可继续演进的主路径，而不是一次性完成所有远程 Agent OS 能力。

## 本版本包含

- OpenPPX Desktop 与 Python/Google ADK 后端进入同一 monorepo，但继续通过版本化 HTTP/SSE Client API 保持前后端分离。
- 三栏工作区：左侧管理 Node、Agent 与 Session，中间进行对话和任务操作，右侧查看 Activity 与 Artifacts。
- 可管理本机 OpenPPX Node，也可通过 Bearer Token 连接可信局域网中的另一台 Node。
- Client API v1 协议握手、Node 身份验证，以及协议不兼容、未授权和离线状态的明确提示。
- 局域网 Token 由 Electron Main 使用系统安全存储加密保存，不写入普通连接配置。
- 生产 Renderer、Electron Main 和 preload 独立构建；安装包不依赖 Vite 开发服务或仓库源码。
- macOS Apple Silicon 未签名 DMG、blockmap 和 SHA-256 校验清单。

## 架构边界

```text
OpenPPX Desktop
  -> Electron Main / secure credential store
  -> Client API v1 (HTTP + SSE)
  -> OpenPPX Node (Python + Google ADK)
  -> one or more configured agents
```

Desktop 和 Node 可以位于同一台机器，也可以位于同一可信局域网的不同机器。当前安装包是薄客户端，不会把 Python 后端、模型凭证、Agent 配置或用户数据打进应用。

## 本地验证基线

发布候选应至少通过：

```bash
pnpm desktop:test
pnpm desktop:typecheck
pnpm desktop:build
pnpm desktop:package:dir
pnpm desktop:package
pnpm desktop:checksum
hdiutil verify apps/desktop/release/OpenPPX-Desktop-0.5.0-beta.1-mac-arm64.dmg
```

还需要从打包后的 `.app` 启动一次，确认：

- 窗口能显示完整三栏界面，而不是空白页或 Chromium 错误页；
- preload IPC 可用且 Renderer 仍处于 sandbox；
- 没有可用 Node 时显示可行动的离线状态；
- 包内只包含构建产物与 package metadata，不包含仓库源码和本机配置。

## 已知限制

- 仅生成 macOS Apple Silicon 包；Windows、Linux 和 Intel macOS 尚未进入本轮验证。
- 未做 Apple Developer ID 签名或 notarization，macOS 可能显示来源验证提示。
- OpenPPX Node 需要单独安装、配置并运行。
- 仅支持一个当前连接目标；尚无多 Node 列表、自动发现和配对。
- 局域网模式适用于可信网络，不应把 Client API 端口直接暴露到公网。
- 尚未提供 TLS 自动配置、SSH tunnel、Tailnet 或公网 Relay。
- Activity 与 Artifacts 只投影真实消息事件；还没有独立的 Artifact 后端 API。
- Desktop 端取消长任务、跨设备重连恢复和完整的两机验收仍需后续迭代。

## 公开发布前仍需完成

1. 在两台真实局域网机器上走通安装、Token 配置、对话与 SSE 事件恢复。
2. 确定签名/notarization 策略，并验证全新 macOS 用户环境的安装体验。
3. 准备真实产品截图、短演示和简洁的安装文档。
4. 为 Python 包和 Desktop 制定一致但相互独立的版本策略。
5. 完成发布提交、Tag、推送与 Release；这些动作需要单独确认。

## 后续演进方向

在不破坏 Client API 边界的前提下，Node 后端可以继续加入更好的 Memory、自演化、长任务、监督与恢复能力。Desktop 则逐步演化成类似 Codex Desktop 的多 Agent 管理工作台，并为未来的远程连接与在线服务保留统一控制面。
