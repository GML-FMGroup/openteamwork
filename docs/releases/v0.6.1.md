# OpenTeamwork v0.6.1 Secure Multi-User History Preview

> 状态：GitHub Pre-release。它面向开发者测试，不应描述为稳定或生产就绪版本。
> 版本边界：本文只描述 `v0.6.1` tag 和对应发布资产中实际包含的能力。

`v0.6.1` 将公开产品名称统一为 OpenTeamwork，并补齐多人登录、分层对话历史访问和不可旁路的非 root Agent 权限边界。共享 Python Runtime、`openppx.*` 模块、Client API 协议标识和 Google ADK 执行模型保持不变。

## 本版本重点

- **OpenTeamwork 产品边界：** UI、CLI、Python 分发包、Desktop 应用、配置目录和环境变量统一为 OpenTeamwork、`otw`、`openteamwork`、`~/.openteamwork` 和 `OPENTEAMWORK_*`；`openteamwork` 保留为长命令入口。
- **管理员部署与用户登录：** 管理员可在 Node 上创建 low、medium、high、root 用户；Desktop 使用邮箱和 Secret 登录，用户只能创建不高于自身等级的 Agent。用户会话一小时过期，远程登录要求同机 HTTPS 反向代理。
- **分层 Session 历史：** Agent 可按名称列出、读取和搜索授权范围内的保留 Session。相同用户遵循 Agent 等级支配；high/root 用户的 high/root Agent 可读取组织内非 root 历史；跨用户 root 用户或 root Agent 历史保持隔离。
- **明确的 Session 生命周期：** Active、Archived 和 Removed 分离。界面删除采用保留式 Removed 状态：从普通历史中隐藏且不可继续对话，但仍可由有权限的历史工具读取和搜索。
- **不可旁路的权限底线：** 非 root Agent 即使声明 `observe`，Tool、Path、Command、Process 和 Network 拒绝仍会执行。Node 数据、其他 Agent Workspace 和未沙箱化 Skill API 不能作为历史 ACL 的替代访问路径；缺少沙箱或代理前置条件时直接失败，不回退宿主机。
- **Agent 权限感知：** 每个 Runtime 向 Agent 注入自己的有效权限等级、历史访问范围和终止性拒绝规则。模型被明确要求不得通过 shell、文件、Skill、API、浏览器、子 Agent 或其他工具重试被拒绝目标。
- **更顺畅的 Desktop：** 已保存登录在一小时内直接恢复已有 Agent 和工作区；本地与远程 Node 使用统一登录表单；Agent 显示名称、流式回复、附件卡片、归档筛选和恢复后的附件标识得到修正。
- **可信本地 HTTPS：** Desktop 通过 Electron 网络栈使用系统信任存储，支持管理员提供的本地 CA/mkcert HTTPS Node，不降低证书校验。

## 安全与数据边界

```text
Authenticated user + invoking Agent privilege
  → named-Agent history resolver
  → hierarchical history ACL + non-disclosing denial audit
  → retained ADK Session projection
  → bounded text / attachment-marker results with citations

Generic Tool / file / command request
  → mandatory non-root Tool and Path floor
  → permission-derived sandbox and Network gate
  → fail closed when the boundary is unavailable
```

第一版历史搜索只覆盖消息文本和附件标识，不读取附件实际内容或 Artifact。Removed Session 的原始记录会保留；物理清除仍是后续独立的管理员能力。

## 已知限制

- 仅正式提供 macOS Apple Silicon Desktop 预览包；没有 Windows、Linux 或 Intel macOS 安装包。
- macOS DMG 未使用 Apple Developer ID 签名或 notarization，系统可能显示来源验证提示。
- OpenTeamwork Node 仍需单独安装、配置和运行；Desktop 安装包不包含 Python、模型凭据或用户数据库。
- 用户 Secret 和权限等级暂不支持自助修改；账号生命周期仍由 Node 管理员通过 CLI 管理。
- Client API 不应直接暴露到公网。远程 Desktop 登录需要在 Node 同机通过受信任 HTTPS 反向代理暴露 loopback Client API。
- 非 root 的脚本型 Skill API 当前禁用；low Agent 只获得审核过的只读 Tool 和历史 Tool 白名单。
- medium/high 的任意命令执行需要配置好的 Docker 隔离和代码出口代理；缺少前置条件时按设计拒绝。
